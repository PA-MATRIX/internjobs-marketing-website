<objective>
Phase 32 embeds Parrot's internjobs tenant as the Workspace SMS/phone pane. Plan 32-02 built the persistent iframe and its inbound postMessage handling (including a `parrot-dial-request` listener that was inert — no dispatcher existed yet). This plan closes the two remaining pieces of the postMessage contract from `.planning/workstreams/team-workspace/WORKSPACE-HANDOFF.md` §4 that live OUTSIDE the pane itself: the combined nav badge (Parrot → Workspace) and the outbound dial-request dispatcher (Workspace → Parrot).

Purpose: badges are how an employee notices a missed call or new SMS while working in Email or Chat — without this, `ParrotEmbedPane`'s `parrot:badge` handling (32-02) has no visible effect anywhere in the UI.

Output: `WorkspaceShell.tsx` renders a badge on the Phone icon (call count) and SMS icon (message count), mirroring the EXISTING `chatUnread`/`chat-unread-change` badge already in that file. `app/lib/parrot-embed.ts` gains `requestParrotDial(number)`, unit-tested.

SCOPE NOTE (read before starting — this is an intentional boundary, not a missed requirement): the contract's Workspace→Parrot `parrot:dial` message is meant to fire from "a Dial button shared elsewhere in Workspace" (e.g. next to a contact's phone number in Chat). Today, Workspace has NO existing UI surface that displays a raw phone number for another person — Chat (`ChatPane.tsx`) is keyed on Mattermost users by email with no phone field synced, and the Admin employee directory (`admin.tsx`) shows capability flags, not phone numbers. Adding a phone-number-bearing UI surface to wire a "Dial" button into would require its own data-plumbing plan (out of scope for a "thin embed" phase). This plan therefore builds and fully tests the generic dispatch contract (`requestParrotDial`) — ready for the FIRST real caller whenever one exists — without inventing a placeholder button that dials nothing real. Document this explicitly in the SUMMARY.

// Phase 32 (32-03): combined Phone/SMS badge, mirrors the chatUnread
// pattern above. ParrotEmbedPane (mounted at the root, survives route
// changes) dispatches this CustomEvent whenever Parrot reports updated
// missed-call/unread-message counts via postMessage.
const [parrotBadge, setParrotBadge] = useState({ calls: 0, messages: 0 });
useEffect(() => {
	if (typeof window === "undefined") return;
	function onParrotBadge(e: Event) {
		const detail = (e as CustomEvent<{ calls?: number; messages?: number }>).detail;
		setParrotBadge({
			calls: Math.max(0, detail?.calls ?? 0),
			messages: Math.max(0, detail?.messages ?? 0),
		});
	}
	window.addEventListener("parrot-badge-change", onParrotBadge);
	return () => window.removeEventListener("parrot-badge-change", onParrotBadge);
}, []);
```

/**
 * Requests that the Parrot embed pre-fill the dialer with `number` and
 * navigate the employee to /phone. Dispatched as a window CustomEvent —
 * ParrotEmbedPane (mounted at the app root, always alive) listens for
 * PARROT_DIAL_REQUEST_EVENT and forwards it as a `parrot:dial` postMessage
 * to the iframe. Per the locked contract (WORKSPACE-HANDOFF.md §2.3) this
 * is PRE-FILL ONLY — the employee must click "Call" once inside the pane;
 * there is no reliable cross-frame auto-dial (no user-activation inside
 * the iframe from a parent-frame click).
 *
 * No caller exists yet in this codebase — see 32-03-PLAN.md's scope note.
 * This is deliberately generic, ready for the first real "Dial" affordance.
 */
export function requestParrotDial(number: string): void {
	if (typeof window === "undefined") return;
	window.dispatchEvent(
		new CustomEvent(PARROT_DIAL_REQUEST_EVENT, { detail: { number } }),
	);
}
```
