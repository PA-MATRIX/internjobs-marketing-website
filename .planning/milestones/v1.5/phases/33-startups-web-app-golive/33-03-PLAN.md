<objective>
Configure Clerk's native Restrictions API on the **employers** Clerk application (the same Clerk app instance now serving `employers.internjobs.ai` as its Secondary-application custom domain — already reconfigured and live per this phase's prior ops) so personal-email signups are rejected at the sign-up form itself, with zero Worker code.

**Why config, not code:** a `user.created` webhook approach was built and then explicitly reverted on 2026-05-27 (commit `67f69e0`, "User pivoted to Option A") in favor of Clerk's built-in Restrictions/blocklist — cleaner UX (rejection at the form, no orphan accounts, no 1-3s race window where a blocked user has a valid session before deletion), zero ongoing Worker handler, no Svix webhook portal step. That decision stands; this plan is the live-apply + verify step for the **employers** app (the underlying Clerk application instance may be the same one that commit configured pre-rename — this script is idempotent specifically so it's safe to re-run regardless of whether that config already landed on this instance or needs to land fresh after the `startups`→`employers` domain pivot).

**API contract (from commit `67f69e0`'s prior live-verified config — reuse exactly):**
- `PATCH https://api.clerk.com/v1/instance/restrictions` body `{blocklist: true, block_disposable_email_domains: true, block_email_subaddresses: true}` — `block_disposable_email_domains` covers Clerk's own curated disposable-email list (mailinator, 10minutemail, etc.) and auto-updates; `block_email_subaddresses` blocks `joe+foo@gmail.com` == `joe@gmail.com` gaming.
- `POST https://api.clerk.com/v1/blocklist_identifiers` with body `{identifier: "*@<domain>"}`, once per domain, for the same 26 domains as `apps/startup/workers/lib/workEmail.ts`'s `BLOCKED_DOMAINS` Set — **PLUS** an explicit enumeration of common `gmx.*` country TLDs (the code-side list pattern-matches `gmx.*` generically via `startsWith("gmx.")`, but Clerk's blocklist only accepts literal identifiers, no TLD wildcards — this is the one place the two lists genuinely can't be expressed the same way, so enumerate the common TLDs to approximate parity: `gmx.com`, `gmx.de`, `gmx.net`, `gmx.at`, `gmx.ch`, `gmx.co.uk`, `gmx.us`, `gmx.fr`, `gmx.es`).

Purpose: closes the "work-email-only signup" requirement of the phase goal without any Worker/webhook code.
Output: a reusable, idempotent ops script + a live-applied + API-verified Clerk Restrictions configuration on the employers app.
</objective>
