<objective>
Close the timeout-budget blocker for real: build the cross-package CI check that Plans 33-01 and 33-02 both reference but neither can build alone (each only has visibility into its own package's constants), then provision the shared `EMAIL_HANDOFF_SECRET` and deploy both Workers so the email-dispatch code from Plans 33-01 and 33-02 is live in production.

**Why this check belongs here, not in 33-01 or 33-02 (iteration-2 checker requirement):** the phase checker found that both plans' prior "regression guard" tests were self-referential — `apps/startup`'s test asserted `apps/startup`'s own constants equal hardcoded numbers, `apps/email-worker`'s test did the same for its own constants, and the two packages have separate CI jobs that never import from each other. Neither test could ever fail due to a change in the other package, which is exactly the two-sides-choose-numbers-independently failure mode the whole fix exists to prevent. This plan is the first point in the dependency graph where BOTH packages' code already exists (`depends_on: ["33-01", "33-02"]`), so it is the correct — and only workable — place for a script that reads both sides' real numbers and checks them against each other.

No Cloudflare dashboard action is required for the deploy portion of this plan — the existing single zone-wide Email Routing catch-all already points at `internjobs-email-ingest`, which is the Worker being extended (not replaced or repointed).

Purpose: (1) turn the latency-budget fix from "documented in two plans' comments" into "mechanically enforced in CI," (2) turn the code from 33-01 + 33-02 into a live path.
Output: `scripts/check-email-timeout-invariant.mjs` + a new CI job that runs it; `EMAIL_HANDOFF_SECRET` in Infisical + bound to both Workers; fresh deployments of `internjobs-startup-mcp` and `internjobs-email-ingest`; a synthetic smoke test proving the handoff works end-to-end before the full live-email verification in Plan 33-05.

  <name>Task 1: Build the cross-package timeout invariant CI check</name>
  <files>scripts/check-email-timeout-invariant.mjs, .github/workflows/ci.yml</files>
  <action>
Create `scripts/check-email-timeout-invariant.mjs` — plain Node ESM (`node:fs` only, zero npm dependencies, runs with plain `node` on Node 22, no `tsx`/TypeScript compilation needed even though one of the two source files it reads is `.ts` — it extracts the constant via text, it does not execute or type-check the file). This is the REAL enforcement mechanism for the latency-budget blocker — Plans 33-01 and 33-02 only assert their own package's numbers in isolation; this script is what actually compares the two packages against each other.

Requirements:

1. Read `apps/startup/workers/routes/email.ts` as text (resolve the path relative to the repo root, e.g. via `new URL('../apps/startup/workers/routes/email.ts', import.meta.url)`, so the script works regardless of CWD). Extract `RESOLVE_TIMEOUT_MS` and `INSERT_TIMEOUT_MS` via a regex matching the exported const declaration, e.g. `/export const RESOLVE_TIMEOUT_MS\s*=\s*(\d+)/` and the equivalent for `INSERT_TIMEOUT_MS`. If either regex fails to match (file moved, constant renamed, no longer exported), exit 1 immediately with a clear error naming the missing constant and file — do NOT fall back to a hardcoded default, a missing constant must fail loudly, not silently pass with a stale assumption.

2. Read `apps/email-worker/src/index.js` as text the same way. Extract `EMPLOYERS_HANDOFF_TIMEOUT_MS` and `OVERHEAD_BUDGET_MS` via the equivalent regex (these are plain `const` + `export` on separate lines per Plan 33-02's Task 1 — match `export const EMPLOYERS_HANDOFF_TIMEOUT_MS\s*=\s*(\d+)` and likewise for `OVERHEAD_BUDGET_MS`; if Plan 33-02 exported them differently, e.g. via a trailing `export { EMPLOYERS_HANDOFF_TIMEOUT_MS, OVERHEAD_BUDGET_MS }`, make the regex tolerant of both an inline `export const NAME = value` and a bare `const NAME = value` declaration, since what actually matters is finding the numeric literal, not the exact export syntax). Same fail-loudly-on-no-match behavior.

3. Compute `innerSum = RESOLVE_TIMEOUT_MS + INSERT_TIMEOUT_MS` and `totalBudget = innerSum + OVERHEAD_BUDGET_MS`. Assert `totalBudget <= EMPLOYERS_HANDOFF_TIMEOUT_MS`.

4. On success: print a one-line summary with all four numbers and the computed inequality (e.g. `OK: RESOLVE_TIMEOUT_MS(4000) + INSERT_TIMEOUT_MS(5000) + OVERHEAD_BUDGET_MS(5000) = 14000 <= EMPLOYERS_HANDOFF_TIMEOUT_MS(20000)`), exit 0.

5. On violation: print all four actual numbers, the computed `totalBudget`, the ceiling it exceeded, and both file paths that need to be reconciled (e.g. `FAIL: RESOLVE_TIMEOUT_MS(4000) + INSERT_TIMEOUT_MS(5000) + OVERHEAD_BUDGET_MS(5000) = 14000 > EMPLOYERS_HANDOFF_TIMEOUT_MS(9000). Fix apps/email-worker/src/index.js's EMPLOYERS_HANDOFF_TIMEOUT_MS or apps/startup/workers/routes/email.ts's RESOLVE_TIMEOUT_MS/INSERT_TIMEOUT_MS so the inequality holds again.`), exit 1.

Then wire it into `.github/workflows/ci.yml` as a new job (cheap enough to just always run — no need to gate on which files changed):

```yaml
  email-timeout-invariant:
    name: email timeout invariant (cross-package)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: node scripts/check-email-timeout-invariant.mjs
```
  </action>
  <verify>node scripts/check-email-timeout-invariant.mjs</verify>
  <done>Script exits 0 against the current live values (4000 + 5000 + 5000 = 14000 <= 20000), printing all four real numbers read directly from both source files (not hardcoded duplicates in the script itself); a deliberate local edit that violates the inequality (e.g. temporarily lowering `EMPLOYERS_HANDOFF_TIMEOUT_MS` below 14000) makes the script exit 1 with a clear message naming both files — verify this manually, then revert the deliberate edit. `.github/workflows/ci.yml` has the new `email-timeout-invariant` job.</done>
