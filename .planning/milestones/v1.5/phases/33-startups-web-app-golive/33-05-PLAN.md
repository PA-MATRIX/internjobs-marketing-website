<objective>
Prove the phase goal is actually true in production — not just deployed — by exercising the full live path with real mail and a real sign-up attempt, then recording evidence. This is the closing verification for Phase 33: "employers.internjobs.ai live + per-startup agent email + work-email-only signup + inbound candidate email reaching the startup pipeline."

Everything Claude can automate (provisioning a test startup, running DB queries, re-checking Clerk API state) happens as `auto` tasks. The things that genuinely require a human/external actor — sending real email from an external mailbox through Cloudflare's real MX servers, and driving a real browser through Clerk's hosted sign-up UI — are the `checkpoint:human-verify` task in the middle.

**Why this plan includes a real bogus-slug send (checker warning-W1 fix):** the fail-safe promise ("an employers.internjobs.ai email NEVER silently disappears," Plan 33-02) was, until this revision, only asserted by unit tests that mock `fetch` and `message.forward` — never exercised against the real Cloudflare Workers email runtime. In particular, nothing had proven that fully draining `message.raw` via `new Response(message.raw).arrayBuffer()` (Plan 33-02's dispatch attempt) still leaves `message.forward()` usable afterward on the REAL runtime — that's a CF-runtime-specific stream/ordering behavior no mock can stand in for. Check 2 below (real bogus-slug send) closes that gap.
</objective>
